# @authenchain/node

Official Node.js and TypeScript SDK for AuthenChain, the infrastructure layer for cryptographic attestation and provenance of AI outputs.

Use it to sign outputs at generation time, carry verifiable provenance through your backend, and verify origin and integrity later without changing your interface between local and production environments.

## Install

```bash
npm install @authenchain/node
```

> **Closed beta:** `@authenchain/node` is not on the public npm registry yet. The package is distributed on request during the closed beta, and this command works unchanged once it is published.

## Quickstart

```ts
import { AuthenChain } from '@authenchain/node'

const ac = new AuthenChain({
  apiKey: process.env.AUTHENCHAIN_API_KEY!,
})

const captured = await ac.captureGeneration({
  output: 'final answer generated by the agent',
  issuer: 'customer-support-agent',
  model: 'gpt-5.1',
  generateMetadataDefaults: true,
  extra: {
    source: 'support-orchestrator',
    prompt_id: 'prompt_123',
  },
})

const verification = await ac.verify({
  content: captured.output,
  provenance: captured.provenance,
})
```

## Why this SDK

- Thin typed wrapper over the AuthenChain HTTP API.
- Designed for Node.js, TypeScript, AI agents, orchestration layers, and LLM backends.
- Hosted API default: `https://api.authenchain.com`.
- Built-in timeout handling, retry support for transient failures, typed errors, and lightweight observability hooks.

## Configuration

```ts
import { AuthenChain } from '@authenchain/node'

const ac = new AuthenChain({
  apiKey: process.env.AUTHENCHAIN_API_KEY!,
  baseUrl: process.env.AUTHENCHAIN_BASE_URL,
  timeoutMs: 10_000,
  retry: {
    maxAttempts: 3,
    baseDelayMs: 250,
    maxDelayMs: 2_000,
  },
  defaultHeaders: {
    'x-org-slug': 'acme-prod',
  },
  onRequest: (event) => {
    console.log('authenchain request', event.method, event.path, event.attempt)
  },
  onResponse: (event) => {
    console.log('authenchain response', event.status, event.traceId)
  },
  onError: (event) => {
    console.error('authenchain error', event.error.name, event.willRetry)
  },
})
```

Retry is optional and only applies to transient failures:

- `429`
- `502`
- `503`
- `504`
- network failures before a response is received

Validation and authorization errors are not retried.

## Base URL

The SDK uses `https://api.authenchain.com` by default. `AUTHENCHAIN_BASE_URL` or an explicit `baseUrl` takes precedence. Localhost is never selected implicitly.

```ts
const ac = new AuthenChain({
  apiKey: process.env.AUTHENCHAIN_API_KEY!,
  baseUrl: 'http://localhost:3000',
})
```

## Idempotent Signing

Every `sign`, `signWithContentHash`, and capture operation automatically creates a `sign:<UUID>` idempotency key. The same key is reused for all internal retries of that operation. Pass an explicit key when retries can cross processes or job executions:

```ts
await ac.sign({
  contentHash: 'a'.repeat(64),
  metadata: { issuer: 'generation-worker' },
  idempotencyKey: 'sign:job_01JABC:attempt_1',
})
```

The server retains the result for 24 hours. Reusing a key with the same payload replays the successful result; a different payload returns `409`.

## Verify Webhooks

Verify the exact bytes received before parsing JSON. The replay store must implement one atomic claim, such as Redis `SET NX EX` or a database unique insert:

```ts
import { verifyAuthenChainWebhook } from '@authenchain/node'

const result = await verifyAuthenChainWebhook({
  secret: process.env.AUTHENCHAIN_WEBHOOK_SECRET!,
  rawBody,
  headers: request.headers,
  replayStore: {
    claim: (nonce, expiresAt) => redis.set(`authenchain:webhook:${nonce}`, '1', {
      NX: true,
      PXAT: expiresAt.getTime(),
    }).then((value) => value === 'OK'),
  },
})

if (!result.valid) throw new Error(`Rejected webhook: ${result.reason}`)
```

## Mock Mode

Mock mode is for tests, demos, local CI, examples, and harness simulations. It avoids network calls, billing, persistent writes, production trust-root material, and real signing keys.

```ts
const ac = new AuthenChain({
  mock: true,
})

const signed = await ac.sign({
  content: 'hello world',
  metadata: {
    issuer: 'mock-example',
    content_type: 'text',
  },
})

const verification = await ac.verify({
  content: 'hello world',
  provenance: signed,
})
```

You can also enable mock mode with `AUTHENCHAIN_MOCK_MODE=true`.

Every mock response includes:

```json
{
  "environment": "mock",
  "mock": true
}
```

Mock Evidence Packs are never externally trustworthy and always keep legal compliance as `not_determined`.

## Privacy And Data Minimization

Use raw `content` only when AuthenChain must compute or verify the content hash.
For sensitive customer data, compute a SHA-256 hash in your environment and send
`contentHash` when raw content does not need to leave that environment.

Do not place API keys, authorization headers, private keys, customer secrets, or
raw regulated records in `metadata.extra`, `metadata.regulatory`, request IDs,
correlation IDs, or example fixtures.

## Regulatory Metadata Example

`metadata.regulatory` is an optional object for AI outputs that need stronger transparency, traceability, audit, and dispute evidence. AuthenChain records, signs, verifies, and exports this metadata as technical evidence. AuthenChain does not determine legal compliance and does not guarantee that a customer workflow satisfies any law or regulation.

The object is part of the signed metadata. If any field inside `metadata.regulatory` changes after signing, verification should fail.

```ts
import { randomUUID } from 'node:crypto'
import { AuthenChain, type RegulatoryMetadataV1 } from '@authenchain/node'

const ac = new AuthenChain({
  apiKey: process.env.AUTHENCHAIN_API_KEY!,
  baseUrl: process.env.AUTHENCHAIN_BASE_URL,
})

const regulatory: RegulatoryMetadataV1 = {
  schema_version: 'regulatory.v1',
  ai_generated: true,
  jurisdiction: 'EU',
  regulatory_context: ['eu_ai_act_article_50'],
  content_type: 'text',
  model_provider: 'openai',
  model_name: 'gpt-4.1',
  system_purpose: 'customer_support_response',
  risk_context: 'limited',
  human_reviewed: false,
  disclosure_required: true,
  disclosure_applied: true,
  label_type: 'human_visible',
  policy_version: 'ai-disclosure-policy-v1',
}

const provenance = await ac.sign({
  content: 'Final AI output shown to the user.',
  metadata: {
    schema_version: '1.0',
    issuer: 'support-answer-service',
    content_type: 'text',
    created_at: new Date().toISOString(),
    nonce: randomUUID(),
    trace_id: randomUUID(),
    regulatory,
  },
})

const verification = await ac.verify({
  content: 'Final AI output shown to the user.',
  provenance,
})
```

`risk_context` should come from customer policy, backend classification, or compliance review. Do not rely on the model output alone to assign it.

Evidence Pack exports include `metadata.regulatory` inside the signed canonical payload and expose technical regulatory evidence fields derived from that signed metadata:

```ts
const evidencePack = await ac.exportEvidencePack({
  traceId: provenance.traceId,
})

const regulatoryMetadata =
  evidencePack.proofs?.[0]?.cryptographicProof?.canonicalPayload?.metadata?.regulatory

const regulatoryEvidence = evidencePack.proofs?.[0]?.regulatoryEvidence
const regulatoryEvidenceSummary = evidencePack.regulatoryEvidenceSummary
const regulatoryEvidenceStatus =
  evidencePack.verificationConclusion?.regulatoryEvidenceStatus
const legalCompliance = evidencePack.verificationConclusion?.legalCompliance
```

`regulatoryEvidenceStatus` is a technical evidence completeness status. It is separate from `trustedStatus` and does not determine legal compliance. `legalCompliance` is always `not_determined`.

For full implementation guidance, see [Regulatory Metadata Developer Guide](../../docs/regulatory-metadata-developer-guide.md) and [Regulatory Evidence Pack Developer Guide](../../docs/regulatory-evidence-pack-developer-guide.md).

## `wrapGeneration` Example

`wrapGeneration` supports either:

- `Promise<string>`
- `Promise<{ output: string; model?: string; provider?: string; raw?: unknown }>`

```ts
const run = await ac.wrapGeneration({
  issuer: 'ops-agent',
  generateMetadataDefaults: true,
  generate: async () => {
    const response = await llm.responses.create({
      model: 'gpt-5.1',
      input: 'Summarize incident INC-204',
    })

    return {
      output: response.output_text,
      model: response.model,
      provider: 'openai',
      raw: response,
    }
  },
  requestId: 'req_wrap_123',
})

console.log(run.output)
console.log(run.provenance.traceId)
```

If your callback throws, the SDK preserves the original error as the cause and adds AuthenChain context around the failure.

## Error Handling

```ts
import {
  AuthenChain,
  AuthenChainApiError,
  AuthenChainNetworkError,
  AuthenChainTimeoutError,
  AuthenChainValidationError,
} from '@authenchain/node'

try {
	  await ac.sign({
	    content: 'hello world',
	    metadata: { issuer: 'agent-router' },
	    generateMetadataDefaults: true,
	  })
} catch (error) {
  if (error instanceof AuthenChainValidationError) {
    console.error('invalid local input', error.message)
  } else if (error instanceof AuthenChainTimeoutError) {
    console.error('request timed out', error.timeoutMs)
  } else if (error instanceof AuthenChainNetworkError) {
    console.error('network failure', error.message)
  } else if (error instanceof AuthenChainApiError) {
    console.error('api failure', error.status, error.code, error.traceId)
  } else {
    throw error
  }
}
```

## Metadata Validation

Metadata is preserved by default before the request is sent.

- Valid JSON-like objects are accepted.
- Deeply nested JSON-serializable objects are allowed.
- Circular references are rejected.
- `bigint`, functions, symbols, and `undefined` values are rejected.
- Wire metadata keys are required by default: `schema_version`, `issuer`, `content_type`, `created_at`, `nonce`, and optional `trace_id`.
- CamelCase metadata keys such as `contentType`, `createdAt`, and `traceId` are rejected in strict mode.
- The SDK does not trim, lowercase, date-normalize, or generate proof-critical metadata unless `generateMetadataDefaults: true` is set.

This keeps SDK behavior aligned with backend truth. For demos, set `generateMetadataDefaults: true`; production integrations should usually provide explicit wire metadata.

## Webhook v1 replay retention

X-AuthenChain-Max-Age is an unsigned acceptance hint. It can shorten but cannot enlarge local acceptance or the 300-second protocol ceiling. The HMAC bytes remain v1.timestamp.nonce.eventId.rawBody. Reserve each valid nonce atomically until timestamp + 300 seconds regardless of the hint, using an integration/secret-version namespace and persistent SET NX plus TTL. Store failure must reject delivery. Verify the original raw bytes before JSON parsing.

## Capture assurance

Schema 1.1 includes signed authenchain.assurance.v1 metadata: A0 attests a submitted hash without observing original content; A1 observes only submitted bytes. A2-A4 are reserved and never emitted by this API. Legacy 1.0 remains verifiable without inferred assurance. These levels do not prove authorship, creation time, model identity, truth or legal compliance.
